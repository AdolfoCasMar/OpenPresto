# Development priorities

The next priorities are broader file-profile coverage, clear review of pending conversions and reliable project workflows across supported desktop platforms.

Work remains on historical stock valuation, some linked sales and proforma variants, source properties whose meaning is not yet established, additional exchange-format variants and wider functional testing. Actual transaction dates that are absent from a source file cannot be recovered by assumption.

A new profile should be supported by representative inputs, explicit expected behavior and tests of persistence, error handling and financial isolation. New features should use the command layer and keep presentation separate from calculation.

Documentation should describe current behavior and its limits. Historical test coverage does not automatically validate a new module or platform.
